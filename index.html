点击分类快速查找，随时回来复习

配置
git config --global user.name "名字"设置全局用户名
git config --global user.email "邮箱"设置全局邮箱
git config --global --list查看所有全局配置
git config --global init.defaultBranch main设置默认分支名为 main
仓库初始化
git init在当前目录初始化新仓库
git clone <url>克隆远程仓库到本地，自动设置 origin
暂存与提交
git status查看工作区和暂存区状态
git add <文件>暂存指定文件
git add .暂存所有改动
git commit -m "message"提交，message 格式：feat/fix/docs/style/chore: 描述
git commit --amend -m "新message"修改最后一次提交的内容或 message
git commit --amend --no-edit修改内容但不改 message
查看历史
git log --oneline简洁查看提交历史
git log --oneline --graph --all图形化显示所有分支历史
git diff查看工作区与暂存区的差异
git diff --staged查看暂存区与上次提交的差异
git reflog查看所有操作历史，终极后悔药
分支操作
git branch查看所有本地分支
git branch -a查看所有分支（含远程追踪）
git switch -c <分支名>创建并切换到新分支
git switch <分支名>切换到已有分支
git branch -d <分支名>删除已合并的分支（安全）
git branch -D <分支名>强制删除分支（未合并也删）
git branch -m <旧名> <新名>重命名分支
合并
git merge <分支名>把指定分支合并进当前分支
git merge --no-ff <分支名>强制产生合并提交，不 fast-forward
变基
git rebase <分支名>把当前分支变基到指定分支，保持线性历史
git rebase --continue解决冲突后继续 rebase
git rebase --abort放弃 rebase，恢复原状
git rebase -i HEAD~n交互式 rebase，整理最近 n 个提交
冲突解决步骤
1. 打开冲突文件，找到 <<<<<<< ======= >>>>>>> 标记三个标记之间是两个版本的内容
2. 手动编辑，保留最终想要的内容，删掉所有标记VS Code 点击按钮或直接编辑均可
git add <冲突文件>3. 标记冲突已解决
git commit4. 完成合并提交（merge 时用）
git rebase --continue4. 继续变基（rebase 时用）
merge vs rebase：公共分支合并用 merge，本地整理历史 / PR 前同步主分支用 rebase。黄金法则：已推送的公共分支永远不要 rebase。
远程管理
git remote add origin <url>添加远程仓库，起别名 origin
git remote -v查看远程仓库地址
git remote set-url origin <url>修改已有远程地址（如从 HTTPS 换 SSH）
推送与拉取
git push -u origin main首次推送并设置上游，之后直接 git push 即可
git push推送到已设置的上游
git push -u origin <分支名>推送新分支到远程
git fetch origin下载远程最新状态，不合并，先看后合
git pull origin main拉取并用 merge 方式合并（会产生合并提交）
git pull --rebase origin main拉取并用 rebase 方式合并（推荐，保持线性）
push 被拒绝的标准处理
git pull --rebase origin main第一步：先同步远程
如有冲突，解决后 git rebase --continue第二步：处理冲突
git push第三步：再推送
PR 流程
git switch -c feature/xxx1. 创建功能分支
开发 + 提交，commit message 关联 issue：closes #n2. 开发
git push -u origin feature/xxx3. 推送分支
GitHub 上开 PR → Code Review → 合并4. 提 PR
git pull origin main5. 本地同步
git branch -d feature/xxx6. 删除本地分支
Fork 工作流（开源贡献）
GitHub 上 fork 原始仓库，clone 自己的副本1. Fork & Clone
git remote add upstream <原始仓库url>2. 添加原始仓库为 upstream
git fetch upstream3. 同步原始仓库最新进度
git rebase upstream/main4. 把本地分支更新到最新
git push origin feature/xxx5. 推到自己的 fork
在 GitHub 上从自己 fork 向原始仓库提 PR6. 提 PR
撤销选择指南
git restore <文件>还没 add → 丢弃工作区改动（不可恢复，危险）
git restore --staged <文件>已经 add → 移出暂存区，改动保留（安全）
git commit --amend刚提交写错了 → 修改最后一次提交（未推送时用）
git reset --soft HEAD~n撤销 n 个提交，改动留在暂存区
git reset --mixed HEAD~n撤销 n 个提交，改动留在工作区（默认）
git reset --hard HEAD~n撤销 n 个提交，改动直接丢弃（危险）
git revert <提交ID>已推送的提交 → 创建新提交抵消，不改历史（安全）
reflog 救命流程
git reflog查看所有操作历史，数字越小越新
看描述找到误操作前的那一行，复制那个提交 ID靠描述定位，不要数序号
git reset --hard <ID>恢复到那个状态（reset 误操作）
git switch -c <分支名> <ID>从那个 ID 重建分支（误删分支）
记住：只要 commit 过，90 天内几乎都能用 reflog 找回来。reset --hard 和 restore 是真正危险的操作，执行前想清楚。

个人项目标准工作流

1
开始新功能
git switch -c feature/功能名 — 永远在 feature 分支上开发，不要直接改 main
↓
2
原子提交
每完成一个独立改动就提交，message 格式 feat/fix/docs: 描述，一次提交只做一件事
↓
3
同步主分支
git pull --rebase origin main — 定期同步，避免积累大量冲突
↓
4
推送分支
git push -u origin feature/功能名 — 推送到远程
↓
5
合并回 main
个人项目直接 merge；团队项目开 PR，等 Code Review 通过后合并
↓
6
清理
git branch -d feature/功能名 — 合并后删分支，保持列表干净

团队协作标准工作流

1
领取任务，创建 Issue
在 GitHub Issues 里记录要做的事，获得 Issue 编号（如 #5）
↓
2
从最新 main 创建分支
git pull origin main 确保本地最新，再 git switch -c feature/xxx
↓
3
开发 + 定期同步
每天或每隔几天 git pull --rebase origin main，避免长期偏离主线
↓
4
提 PR，关联 Issue
PR description 里写 closes #5，PR 保持小而专注，一个 PR 只做一件事
↓
5
Code Review
根据意见修改后继续推送到同一 feature 分支，PR 自动更新
↓
6
合并 + 同步
PR 合并后 git pull origin main 同步本地，删掉 feature 分支
团队铁律：永远不直接推 main · PR 保持小而专注 · 定期同步主分支 · 不 force push 公共分支

遇到问题怎么办

push 被拒绝，提示 remote contains work...
git pull --rebase origin main → 解决冲突（如有）→ git push
合并出现冲突，有 <<<<<<< 标记
打开文件手动编辑保留最终内容，删掉所有标记 → git add 文件 → git commit
commit message 写错了
还没推送：git commit --amend -m "新message"
已推送：只能用 revert 或接受
误用 reset --hard 删掉了提交
git reflog 找到误操作前的 ID → git reset --hard <ID>
误删了分支
git reflog 找到该分支最后一个提交 ID → git switch -c 分支名 <ID>
已推送的提交有 bug 需要撤销
git revert <提交ID> → git push（不改历史，安全）
想把队友的最新 main 同步到我的 feature 分支
git switch feature/xxx → git pull --rebase origin main
不小心在 main 上做了修改没提交
git stash 暂存改动 → git switch -c feature/xxx → git stash pop 恢复改动
想参与开源项目
Fork → Clone → git remote add upstream <原始仓库> → 开分支开发 → 提 PR
把密码文件提交了
立刻撤销密钥 → git filter-repo --path 文件 --invert-paths → force push → 团队重新 clone
